# Sample campaign

One complete campaign, generated by this application against live providers on
15 September 2026. Included because the assignment asks for it when the project
is not hosted:

> *"If hosting is unavailable, provide reproducible local setup instructions.
> Include one sample campaign with research output, both images, and the video."*

| File | What it is |
|---|---|
| `campaign.json` | Full record — brief, agent trace, sources, all three angles, the creative spec, and per-stage cost |
| `image_1x1.png` | 1080×1080 export |
| `image_9x16.png` | 1080×1920 export |
| `campaign.mp4` | 8-second vertical video, 1080×1920 |
| `master-scene.png` | The master scene both images were edited from |

## What to look at in `campaign.json`

**`research.tool_calls`** — each entry has the agent's own stated reason for the
call, the arguments, the result summary, and the duration. This is the trace the
assignment asks to be observable.

**`research.sources`** — every page the agent actually read, with title, URL,
access timestamp, and the excerpt used as evidence.

**`research.angles`** — three angles. Note the field split: `audience_insight`
must trace to a retrieved source and cites it in `source_urls`, while `hook` and
`visual_direction` are labelled as creative interpretation. `unsupported_numbers`
is empty here, meaning every figure in the copy appears in retrieved text.

**`usage`** — real cost per stage, read from the provider's own reported figure
rather than computed from list prices. `cost_is_reported: true` means every call
in that stage returned its own billed amount.

## How the two images stay consistent

`master-scene.png` is generated once from the creative spec. Each export is then
produced by sending that image *back into the model as an input image* to be
recomposed for its aspect ratio — so the 9:16 is derived from the master's
pixels, not from a second prompt. Compare the product, label text, lighting and
props across all three files.

The headline, body copy, CTA and brand lockup are rendered by Pillow, not by the
image model, so the copy is always exactly what the spec approved.

## Reproducing this

A reviewer with no API keys can run the entire pipeline:

```bash
cd backend && FIXTURE_MODE=1 ./run_fixture.sh
```

That exercises every stage end to end with canned data — the orchestration,
persistence, retry and overlay code all run for real. The generated *photographs*
are placeholders, because there is no image model to call; the files here are
what the same code produces against live providers.
